

> ### 똑똑 - 상명대학교 동아리 리쿠르팅 서비스

"똑똑"은 학생들이 혼재된 동아리정보와 비효율적인 동아리 업무 처리과정을 일원화하여 제공하는 서비스 입니다.<br>
### 📌서비스 소개
**똑똑은 동아리 정보를 한 곳에서 확인하고 지원부터 결과 안내까지 전 과정을 간편하게 관리할 수 있는 동아리 리쿠르팅 서비스입니다.**

동아리 임원진이 기존에 겪던 분산된 정보 관리, 개별 지원자 확인, 반복적인 합격 안내 등 비효율적인 업무 흐름을 개선하기 위해 제작되었습니다.

지원자는 **동아리 탐색 → 지원 → 상태 확인**까지 매끄럽게 경험할 수 있고 임원진은 **지원자 관리·평가·결과 전송**을 모두 한 서비스에서 처리할 수 있습니다.

</br>

### 왜 기획했나요?🤔
IT동아리 임원진을 해보면서 느꼈던 리쿠르팅 과정에서의 불편함 때문이였습니다. 
구글폼을 이용한 지원과정에서 **지원자들의 정보를 일일히 찾아야하고 지원 결과를 전송함에 있어도 하나하나 전송해야하는 불편함 때문에 비효율적**이라고 생각했습니다.  
이를 개선할 서비스가 필요해졌고 저 뿐만 아닌 동아리 임원진이라면 불편함을 느끼고 있을거라고 생각했습니다. 그래서 많은 학우들이 저희 서비스를 통해 훨씬 간편한 리쿠르팅 경험을 제공해주고 싶어 기획을 하게되었습니다.

</br>

### 프로젝트에서 어떤 역할을 했나요?
초기 아이디어를 구체화해 프로젝트의 비전을 명확히 제시하고, 요구사항 정의서·기능 명세서·FlowChart를 작성하며 전체적인 기획을 주도했습니다. 회의 아젠다 정리와 의사결정 기록화를 통해 협업 효율을 높였으며, 직관적인 디자인 방향을 제안해 팀이 빠르게 합의하고 실행할 수 있는 환경을 만들었습니다.

기술스택을 정할 때는 서비스의 특성과 팀원이 효율적으로 개발할 수 있는 것을 고려하여 기술 스택을 정하고 개발 기간이 촉박했기에 애자일개발론을 이용해 개발을 진행했습니다. 

담당 페이지 개발뿐만 아니라 **전반적인 아키텍처 설계, 성능 최적화, 에러 트래킹 및 서버 안정화 시스템을 구축**하며 **서비스의 안정성과 개발 생산성을 높였습니다. 또한 AI 도구를 활용해 퍼블리싱의 속도를 높이고 PR리뷰 자동화**를 했습니다.

</br>

## 기술 스택
### 1) Next.js 선택 (SEO · SSR · 라우팅 최적화)
- 동아리 정보를 검색해서 들어오는 사용자가 많은 구조를 고려해 SEO가 중요하다고 판단
- SSR 기반으로 검색 노출과 첫 렌더링 성능을 확보하기 위해 React 대신 **Next.js 채택**

### 2) TanStack Query 사용 (장기적 유지보수, 상태 관리 일관성)
- Next의 fetch만으로는 로딩/에러/낙관적 업데이트 등 UI 상태 관리 비용이 크다고 판단
- 서버 상태 관리의 일관성과 DX 향상을 위해 **React Query 도입**
- 참고 : https://velog.io/@sik02/Next.js에서-react-query를-왜-써

### 3) Styling: Vanilla Extract 선택 (성능, RSC 호환성)
- CSS-in-JS는 런타임 비용 & RSC와의 충돌 위험 존재
- 빌드타임 스타일 생성, 타입 안정성, SSR 최적화를 모두 충족하는 **Vanilla Extract 선택**
- 참고
